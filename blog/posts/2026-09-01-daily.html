AI 写代码有个很烦的问题：几十行能解决的事，它常写出几百行，抽象层、配置项、工具函数全配齐，能跑但难维护。最近看到一个开源项目 Ponytail 专门解决这个问题。

1. Ponytail 像个惜字如金的资深程序员：优先用现成能力、删死代码、避免重复造轮子，还会揪出那些暂时没人需要的扩展设计。核心命令 /ponytail-review 专门审代码改动，告诉你哪段该删、哪里能写更短。

2. 直接告诉Agent：
“Add a rule & a hook that always runs /ponytail-review before committing/pushing anything”
让 AI 每次提交或推送前，先做一次 Ponytail 审查。

3. 有两层约束：
Rule 写进项目规则，约束 Codex 每次提交前必须审查；
Hook 挂在 Git 的 pre-commit / pre-push，检查没过就拦下提交或推送。

4. 实际流程：
AI 写代码 → /ponytail-review 查过度设计 → 删减代码 → 跑测试 → commit → push
相当于给 AI 加了道提交前质检。

5.
一个细节要注意：/ponytail-review 通常是 Agent 里的 Skill 命令，而 Git Hook 只能跑终端命令。想做成真正的强制门禁，还得写个可执行脚本把两边接起来——只写 Rule 更像固定提醒，配上能实际执行的 Hook 才算强制审查。

项目地址：https://t.co/yjgHcu2n2N
