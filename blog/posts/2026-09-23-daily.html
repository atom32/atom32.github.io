二、绕过封号，代价是换个东西担风险

Claude Code 封号的老问题今天出了个解法，路子有点野：借一台 Grok Bot 的云端虚拟机当跳板。因为那台机器是干净的美国 IP，登录进去之后，编程任务还是别的任务，都能从那里发出去。发帖人的兴奋是真实的，「肉身出海不行就 Agent 出海」这句总结得挺准。

这个方法我持保留态度。账号跑在别人的云主机上，等于把登录凭据交给了第三方平台，封号风险是降下去了，数据风险反而升上来了。省下来的麻烦换了个地方攒着，不算凭空消失。

同一天还有一条正经的省钱办法，来自宝玉。他的思路是把写方案和执行拆开：让 Fable 出设计稿，然后进循环，Opus 负责执行，Fable 负责验收，跑完一轮再进下一轮。他自己的说法是被 token 价格逼出来的。这类分工和下面那条模型编排的新闻其实是同一个方向。
