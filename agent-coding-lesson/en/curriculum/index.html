Course architecture

Double-layer agent harness curriculum

Learn Claude Code is the lab: twelve runnable mechanisms. Claude Reviews Claude is the field guide: the same ideas under production pressure. This map ties each toy mechanism to the real subsystem it prepares you to read.

Middle summary

Review the teaching focus, mental model, lab mechanism, production bridge, and checkpoint for each session.

Advanced chapters

Open the production anatomy layer, starting with QueryEngine, tool systems, and permission pipelines.

Glossary

Normalize core vocabulary such as agent harness, tool calling, compaction, and task board.

Layer 1: Lab

Build a minimal harness one mechanism at a time. Every session is small enough to run, modify, and break on purpose.

Layer 2: Production anatomy

Revisit the same mechanism inside Claude Code, where streaming, safety, persistence, teams, and cost all become first-class.

s01The Agent Loop

How does a model become an agent with one loop and one tool?

What does that loop need before it can survive real users?

The lab loop teaches tool_use and tool_result. QueryEngine keeps that kernel but adds streaming, usage accounting, retries, model fallback, and message normalization.

Practice: Add a max-round limit and a tiny retry wrapper to s01, then compare the shape to QueryEngine's recovery matrix.

s02Tools

How do new abilities enter the harness without rewriting the loop?

How do 42+ tools stay safe, searchable, cache-stable, and UI-ready?

The dispatch map becomes a full Tool contract: schema validation, permission checks, concurrency flags, rendering, result storage, and sandboxed execution.

Practice: Turn one s02 handler into a small object with schema, read-only status, and validation before it executes.

s03TodoWrite

How can the harness help the model maintain intent over many steps?

Where do reminders, plans, and task state appear in a real conversation?

TodoWrite is a visible planning surface. In Claude Code, similar nudges arrive as attachments, plan-mode context, task reminders, and team coordination state.

Practice: Make the todo reminder configurable by turn count and show when it is injected into messages.

s04Subagents

How does a subagent keep noisy work out of the main context?

How are real workers spawned, isolated, supervised, and summarized?

The toy subagent uses independent messages. Production workers add backends, identity, task records, permission delegation, and completion notifications.

Practice: Log every subagent request and final summary to a small JSONL file so the main agent can audit delegated work.

s05Skills

How can knowledge load only when the model needs it?

How do skills, plugins, MCP tools, and slash commands form an extension system?

SKILL.md loading becomes a layered extension architecture: discovery, command conversion, hook integration, plugin packaging, and dynamic context deltas.

Practice: Add skill metadata and a simple search hint, then make the model request the skill before seeing the full body.

s06Compact

How does an agent keep working when context fills up?

How does a real system reclaim tokens without destroying continuity or cache value?

The lab's three layers map to microcompact, session-memory compact, and full LLM summaries, with API invariants, cache edits, thresholds, and circuit breakers.

Practice: Record the before and after token estimate for each compact layer and show what was replaced.

s07Tasks

How do goals survive outside the current chat turn?

How are sessions, tasks, resumes, forks, and durable state represented?

The task board is durable control-plane state. Claude Code extends that idea with JSONL sessions, parent chains, task variants, and background notifications.

Practice: Add a task history log so every state transition can be replayed after a crash.

s08Background Tasks

How can slow work finish without blocking the agent's next thought?

How does background work get prioritized, retried, and reintroduced?

A background thread and notification queue become task-state variants, completion XML, API priority rules, and foreground/background retry differences.

Practice: Add status, started_at, ended_at, and failure output to background task notifications.

s09Agent Teams

How do multiple agents coordinate with only files?

Why would a real swarm still use file mailboxes and locks?

The JSONL inbox grows into a crash-safe mailbox with locks, team config, backend detection, leader-worker rules, and permission delegation.

Practice: Add message IDs and lock-protected append/read operations to the toy mailbox.

s10Team Protocols

How do teammates negotiate decisions without ad hoc messages?

How do plan approval, shutdown, and permission requests share one protocol shape?

The request-response pattern becomes structured control messages routed through SendMessage and reinforced by lifecycle hooks.

Practice: Implement one new protocol, such as review_request/review_response, using the same request_id correlation.

s11Autonomous Agents

How does a teammate decide what to do without being assigned?

How do autonomous workers stay bounded by team state, reminders, and leadership?

Idle polling and task claiming become an autonomous worker loop backed by team context, mailbox polling, plan approval, and task notifications.

Practice: Add lease expiry to claimed tasks so abandoned work can be reclaimed safely.

s12Worktree + Task Isolation

How do parallel agents avoid stepping on the same files?

How does production coordinate worktrees, cleanup, settings, and recovery?

Task/worktree binding turns intent into an isolated execution lane. Production adds backend-specific spawning, cleanup hooks, config propagation, and lifecycle telemetry.

Practice: Add an event replay view that reconstructs active worktrees from tasks plus events.jsonl.
