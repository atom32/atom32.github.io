コース入門

このコースの主題はプロンプト技ではなく、実行時エンジニアリングです

coding agent はモデルと system prompt だけではありません。長く動かすために重要なのは harness です：message loop、tool protocol、context budget、永続状態、permission boundary、ユーザーが制御できる UI。このコースでは 12 個の小さな実装で仕組みを分解し、Claude Code の実システムと比較します。

基本となる見方

LLM を推論の核、harness を知覚・行動・記憶・制約を与える工学的な身体として捉えます。agent の失敗がモデル能力の問題か、runtime 設計の問題かを見分けられるようになります。

Harness Engineering とは

モデルの周囲に実行システムを作ることです。messages を構造化し、tools を宣言し、tool calls を実行し、tool results を戻し、context、permission、retry、log、task、recovery を管理します。

Agentic Loop / ReAct とは

ReAct は Reason -> Act -> Observe のループです。coding agent では、モデルが次の行動を選び、tool_use を出し、harness が実行し、tool_result を戻し、モデルが止まるまで繰り返します。

なぜ Tool Calling から始めるのか

tool calling はモデルと現実世界の境界です。実運用の tool は単なる関数ではなく、名前、schema、permission policy、executor、出力形式、error strategy を持つ契約です。

コアパターン

すべての AI コーディングエージェントは同じループを共有する：モデルを呼び出し、ツールを実行し、結果を返す。実運用ではこの上にポリシー、権限、ライフサイクル層が重なる。

agent_loop.py
while True:
    response = client.messages.create(messages=messages, tools=tools)
    if response.stop_reason != "tool_use":
        break
    for tool_call in response.content:
        result = execute_tool(tool_call.name, tool_call.input)
        messages.append(result)
