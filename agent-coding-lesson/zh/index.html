课程导论

这门课聚焦 Agent 的运行时工程

一个能写代码的 Agent 需要模型、system prompt 和完整的 harness 共同工作。长期运行能力主要取决于消息循环、工具协议、上下文预算、状态持久化、权限边界和用户界面。本课程用 12 个最小实现拆开这些机制，再对照真实 Claude Code 子系统理解生产复杂度。

本节课要建立的心智模型

把 LLM 看作推理核心，把 harness 看作让它感知、行动、记忆和受约束的工程外壳。你会学会判断一个 Agent 系统缺的是模型能力，还是运行时机制。

什么是 Harness Engineering

Harness engineering 是围绕模型搭建可执行系统：组织 messages，声明 tools，执行 tool calls，注入 tool results，管理上下文、权限、重试、日志、任务和恢复。

什么是 Agentic Loop / ReAct

ReAct 可以理解成 Reason -> Act -> Observe 的循环。在代码 Agent 里，它表现为模型思考下一步，发出 tool_use，harness 执行工具，把 tool_result 放回上下文，直到模型停止调用工具。

Tool Calling 为什么是入口

Tool calling 是模型接触真实世界的边界。每个工具都应该以契约方式定义：名称、schema、权限、执行器、输出格式和错误策略。

核心模式

所有 AI 编程 Agent 都共享同一个循环：调用模型、执行工具、将结果写回上下文。生产系统会在这个循环上叠加策略、权限和生命周期控制。

agent_loop.py
while True:
    response = client.messages.create(messages=messages, tools=tools)
    if response.stop_reason != "tool_use":
        break
    for tool_call in response.content:
        result = execute_tool(tool_call.name, tool_call.input)
        messages.append(result)
